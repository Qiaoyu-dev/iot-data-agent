# W2 阶段说明（2026-11-09 ~ 2026-11-15）

> 一句话：把一个能跑的单轮 RAG demo，变成了有记忆、能流式、有错误处理、可回归测试的
> 服务雏形。

## 一、本周完成了什么（每条都可验收）

| 能力 | 落地文件 | 怎么验收 |
| --- | --- | --- |
| Agent 自主调用工具（知识检索 + Pandas 统计） | `agent/graph.py`、`tools/` | 问「温度平均值多少」，回答里有真实统计值 |
| 多轮对话记忆 | `agent/graph.py`（MemorySaver） | 同 thread_id 两轮，第二轮记得第一轮信息 |
| 异步封装 | `api/main.py` | 并发 3 个请求，总耗时接近单次而非 3 倍 |
| SSE 流式输出 | `api/main.py`（/chat/stream） | `curl -N` 能看到逐段输出 |
| 统一错误处理 | `api/errors.py` | 空消息返回 422 且带 request_id |
| P0 冒烟回归 | `scripts/smoke_test.py` | 一条命令输出「通过 6/6」 |
| Streamlit 前端 | `web/app.py` | 页面上能对话、能上传 CSV 出图 |

## 二、现在这个服务能做什么

1. **多轮问答**：同一会话内保持上下文，能指代前文（「它」指上一轮提到的设备）。
2. **知识库检索**：从切分好的文档里召回片段，回答时用 [1][2] 标注来源。
3. **无关问题拒答**：检索相似度低于阈值时不硬编，明确说没找到。
4. **流式输出**：边生成边推给前端，首字延迟明显低于整段返回。
5. **结构化工具调用**：温度统计这类计算交给 Pandas 工具，不让模型自己算。
6. **可观测**：每个请求有 request_id，出错时日志能对上。

## 三、已知限制（诚实清单）

- 评测集只有 10 条，样本小，Hit Rate 指标波动大，正在扩到 50 条。
- 检索只做了向量召回，没有 rerank，长文档下精度有限。
- 记忆是进程内 MemorySaver，重启即丢，没接持久化。
- 没有鉴权，只能本地跑，不能直接对外。
- 单实例部署，没有并发压力测试。
